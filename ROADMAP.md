# Cybersecurity Playground — Roadmap

Cybersecurity Playground is a long-term project.

This roadmap describes the direction in which the project is evolving. It is not intended to be a rigid schedule or a promise of fixed delivery dates.

The project will evolve as the learning experience, technology, cybersecurity landscape, and community evolve.

---

## Where We Are Going

Cybersecurity Playground is being developed progressively:

**Foundation → Learning Path → Practical Labs → Advanced Domains → Community → Continuous Improvement**

Each stage builds upon the previous one.

---

# Phase 2 — Core Learning Path

### Objective

Build a structured cybersecurity learning journey from fundamental concepts toward practical security skills.

### Planned Areas

- [ ] Networking Fundamentals
- [ ] Linux Fundamentals
- [ ] Kali Linux
- [ ] Reconnaissance
- [ ] Scanning and Enumeration
- [ ] Web Security
- [ ] Vulnerability Assessment and Penetration Testing

### Principle

The learner should understand the underlying technology before being introduced to specialized security tools.

---

# Phase 3 — Advanced Security Domains

### Objective

Expand the learning journey into broader and more specialized areas of cybersecurity.

### Planned Areas

- [ ] Cloud Security

- [ ] Defensive Security
- [ ] Detection and Response

# Phase 4 — Practical Learning Environment

### Objective

Transform the repository from a collection of learning materials into an increasingly interactive cybersecurity playground.

### Planned Capabilities

- [ ] Guided hands-on labs
- [ ] Practical exercises
- [ ] Challenge-based learning
- [ ] Troubleshooting exercises
- [ ] Realistic scenarios
- [ ] Defensive and offensive simulations
- [ ] Reflection and investigation exercises
- [ ] Improved learner navigation
- [ ] Supporting resources

The emphasis will remain on learning through experimentation rather than simply following instructions.

---

# Phase 5 — Book + Repository Integration

### Objective

Develop the Book and Repository as two complementary parts of the same learning experience.

### Planned Work

- [ ] Establish clear relationships between Book chapters and Repository modules.
- [ ] Align terminology across the Book and Repository.
- [ ] Create practical exercises that reinforce Book concepts.
- [ ] Add Repository references from relevant Book sections.
- [ ] Ensure the Repository expands upon the Book rather than simply duplicating it.
- [ ] Maintain consistency as both projects evolve.

### The Relationship

> **The Book explains. The Repository lets you experience.**

Together they form the **Cybersecurity Playground Learning Experience**.

# Phase 7 — Continuous Improvement

Cybersecurity Playground should never be considered finished.

Cybersecurity changes.

Technology changes.

Threats change.

Defenses change.

Learning methods change.

Therefore, the project will continuously evolve.

Future improvements may include:

- New cybersecurity domains.
- New learning formats.
- New practical environments.
- Improved exercises.
- Better explanations.
- Community feedback.
- New technologies and security challenges.

---

# Guiding Principles

Regardless of how the roadmap changes, the project will remain guided by the principles established in the Manifesto:

- Understand before operating.
- Build from first principles.
- Learn by doing.
- Treat mistakes as part of learning.
- Use tools to explore concepts.
- Develop offensive and defensive thinking.
- Practice responsibly.
- Value understanding over memorization.
- Keep learning.

---

# Long-Term Direction

The roadmap is intentionally flexible.

Some planned work may happen earlier.

Some may change.

Some may become unnecessary.

New opportunities may emerge.

The roadmap should therefore be treated as a **living document**, not a contract.

The destination matters.

The exact route may change.
